# 포트폴리오 사례: 스킬의 수보다 선택의 근거

## 문제와 목표

개인 AI 작업 환경에 스킬이 늘어나면 같은 목적의 도구가 겹치고, 어떤 순서로 함께 써야 하는지 판단하기 어려워집니다. 목록에 등록된 것과 실제 실행할 수 있는 것도 다릅니다. 설명서가 흩어져 있으면 추천의 근거와 현재 조건을 재확인하는 비용이 커집니다.

이 프로젝트의 목표는 스킬 실행을 자동화하는 대신 **작업에 맞는 후보를 고르고, 필요한 조건과 불확실성을 확인하는 과정**을 짧게 만드는 것입니다. 결과물은 한국어 로컬 UI, 공유 검색·검사 코어, 선택적 MCP, 근거에 제한된 선택적 AI 답변입니다.

## 사용 흐름

1. 카테고리와 검색으로 후보를 찾거나 작업 목표로 로컬 추천을 받습니다.
2. 설명서와 원문 위치를 확인하고 필요한 스킬을 장바구니에 담습니다.
3. 문서에 근거한 연결 관계, 요구사항, 미확인 조합을 확인합니다.
4. 선택과 근거를 저장하거나 요청문으로 내보내 다음 작업에 전달합니다.
5. 필요할 때만 전송할 내용을 검토하고 AI 설명을 요청합니다.

세 개의 탭은 같은 자료를 탐색·검색·작업 목표라는 다른 입구로 보여줍니다. 장바구니는 선택을 화면에 유지하고, 근거는 접어서 제공해 목록을 읽는 흐름을 방해하지 않으면서 다시 확인할 수 있게 했습니다. 키보드 탭 이동, 모달 문서 읽기, 작은 화면의 재배치를 구현했습니다. 이 구현이 전체 접근성 적합성 인증을 뜻하지는 않습니다.

## 핵심 설계 선택

| 선택 | 이유 | 받아들인 제한 |
| --- | --- | --- |
| Python 표준 라이브러리 + Vanilla JS | 기본 실행의 설치 부담을 줄이고 흐름을 직접 추적하기 위해 | 프레임워크가 제공하는 관리 기능은 직접 필요한 범위만 구현 |
| SQLite FTS5 trigram | 로컬 저장과 한국어 부분 일치 검색을 별도 서버 없이 처리하기 위해 | 문장 의미·복잡한 동의어의 검색 재현율은 제한됨 |
| 원문 경로·줄 번호와 두 단계 읽기 | 추천에서 근거까지 확인할 수 있도록 | 원문의 내용과 품질이 결과의 상한을 결정 |
| 명시적 조합 규칙 | 검토 가능한 근거와 미확인 상태를 보존하기 위해 | 모든 스킬 쌍의 실제 호환성을 판정하지 않음 |
| 선택적 AI + 서버 검증 | 설명 능력을 추가하되 후보와 근거의 범위를 고정하기 위해 | 비용·공급자 접근 권한·외부 전송 판단이 추가됨 |
| 직접 작성한 예제로 시작 | 개인 환경 없이 재현 가능한 공개 패키지를 만들기 위해 | 실제 개인 설치 환경을 대표하는 성능 평가 자료는 아님 |

LangChain과 벡터 DB는 현재 흐름에 필요하지 않아 추가하지 않았습니다. 검색 평가에서 키워드 방식의 누락이 확인되면 별도로 비교할 수 있지만, 측정 전에 의존성을 늘리지는 않았습니다.

## 검증 방법과 증거의 범위

| 층 | 확인하는 내용 | 확인하지 못하는 내용 |
| --- | --- | --- |
| Python 단위·통합 테스트 | 검색·읽기·조합 조건, 입력 검증, AI 미리보기와 원문 변경, 예산·취소·응답 계약 | 실제 공급자의 모든 응답·네트워크 조건 |
| 데모 UI 스모크 | 예제 카탈로그 탐색, 문서 읽기, 장바구니와 화면 흐름 | 모든 브라우저·기기·접근성 요구사항 |
| AI UI 스모크 | 모의 응답에서 미리보기·요청·오류 표시 흐름 | 실제 API 인증과 최신 모델 가용성 |
| 공개 패키지 이식성 확인 | 개인 경로와 외부 인벤토리 없이 예제로 시작하는지 | macOS 및 모든 개인 설치 환경의 검증 완료 |

공개 커밋은 Windows/Ubuntu의 Python 검사 4개와 Ubuntu Chromium UI 검사 1개가 GitHub Actions에서 모두 통과했습니다.

테스트 실행 명령은 [README](../README.md#검증과-구현-범위)에 있습니다. 테스트 개수와 패키지 실행 결과는 실제 최종 검증 결과를 기준으로 해석해야 합니다. 테스트 파일의 존재나 과거 결과를 새 패키지의 통과 결과로 간주하지 않습니다.

성공 기준은 추천된 스킬 수가 아니라 근거를 열어 확인할 수 있는지, 미확인 관계를 숨기지 않는지, AI가 범위 밖 ID를 반환했을 때 거부하는지입니다. 사용자 시간 절감률·추천 정확도·모델 간 우열에 대한 정량 벤치마크는 수행하지 않았습니다.

## 남은 과제

- 실제 작업 질의와 정답 근거를 갖춘 검색 평가 집합을 만들어 누락과 잘못된 일치를 측정하기
- 규칙이 다루지 않는 조합을 우선순위에 따라 검토하고 근거 갱신하기
- macOS 및 보조기술에서 실행·접근성 확인하기
- 모델·API 버전·코드 내 비용 가정이 바뀔 때 회귀 검증하기

현재 결과물은 로컬에서 검토 가능한 선택 도구입니다. 범용 스킬 최적화, 자동 실행, 모든 도구의 호환성 보장으로 범위를 넓혀 설명하지 않습니다.
